## 0. 一句話定位

**K1 = 使用者訊息進入 Agent 迴圈前的第一道閘門**：用大腦容器自帶的 EmbeddingGemma-300M 當特徵提取器，加一個自訓練的線性分類頭，在 0.1 秒內判斷「這則訊息回答前需不需要查記憶／該走哪條路」，低置信度自動升級給 LLM。

## 1. 為什麼是這個架構（全部實測數據）

2026-09-21 三方 benchmark（同一把尺：39 題 K1 ground truth，取自 $9 事件 179 則真實對話）：

| 方案 | 4 類 | 二元化（查/不查） | 備註 |
|---|---|---|---|
| Laya 421M zero-shot | 35.9% | 61.5% | 需檢索題 86% 漏查——危險方向；英文同款題也 fail=能力問題 |
| EmbeddingGemma 300M zero-shot | 67% | 77% | 中文語意理解強 |
| **EmbeddingGemma + 線性頭（LOO-CV）** | **79%** | **97%** | 唯一錯誤是誤查方向＝安全側；自訓練 0.01s/次 |

三個關鍵結論：
1. **每個使用者安裝 App 就有這個模型**（大腦容器配套、tflite、179MB）——零額外下載，符合「不是每個人都會裝本地模型」的現實。
2. **決策能力來自線性頭，不來自模型本身**——頭是 768×N 的小矩陣，純矩陣乘，任何機器都跑得動，背景自訓練不需 DGX。
3. **底座可換**（模型跟隨鐵則）：特徵提取器介面化，未來換任何嵌入模型，線性頭跟著重訓即可。

## 3. 標籤體系（v1，四類）

| 標籤 | 定義 | 觸發後路徑 |
|---|---|---|
| `need_memory_lookup` | 答案依賴私有脈絡：身份、歷史、測試結果、排程、儲存紀錄 | 查 agent_memories＋memories（向量優先，FTS 兜底） |
| `repeat_query` | 重複再問（$9 死因之一） | 查「最近問答快取」先於全庫檢索——同題不重燒 |
| `direct_action` | 畫布操作、修程式碼、排任務等執行指令 | 直達工具層 |
| `general_chat` | 閒聊、打招呼、翻譯、意見 | 直接 LLM 回應 |

二元化（`need`/`no`）是守門員的生死題：LOO-CV 97% 即此口徑。4 類細分供路由與統計用。

## 4. DecisionHead 規格（新檔案 `lib/services/decision/`）

```
decision_head.dart      — 純 Dart softmax regression（~150 行）
                          W: List<Float64List>（768×N）、b: 偏置
                          predict(embedding) → (label, confidence)
                          train(samples) → 新 W/b（SGD, 300 epochs, <1s）
decision_store.dart     — 權重持久化（JSON 檔，brain_state/ 目錄）
                          含 model_version、trained_at、sample_count
decision_sample_log.dart — 樣本累積器（讀 causal_ledger 餵訓練）
```

設計鐵則：
- **零外部依賴**——不用 ML 套件，矩陣乘手寫（768 維×4 類＝3072 次乘加，微秒級）。
- **單調升級**——新訓練的頭必須在保留集上 ≥ 舊頭才替換（防止爛樣本污染；對齊 embed_source 單調升級鏈的先例）。
- **權重檔可刪可重建**——樣本在 ledger、頭只是衍生物，資料主權在使用者。

## 5. 自訓練迴路（使用者的「越用越懂」）

**訓練樣本 = K1 判斷 × 事後結果**，全自動、零標註：

| 事後結果 | 標籤回饋 |
|---|---|
| K1 判 `need` → 檢索命中且 LLM 採用 | 正樣本（label=need，可信度高） |
| K1 判 `no` → LLM 事後自己發起檢索 | **負樣本（label 應為 need）——最有價值的錯題** |
| K1 判 `direct` → 工具執行成功 | 正樣本 |
| escalate 案例 | LLM 的最終選擇即標籤（蒸馏來源） |

觸發與節奏：樣本 ≥200 或距上次重訓 ≥7 天，App 閒置時背景跑（<1s），完成寫 `decision_store`＋ledger 留痕。

冷啟動三階段：
1. **裝機 Day 0**：規則層＋錨點 zero-shot（67% 水準，笨但不會自信地錯）
2. **使用中**：樣本累積（無感）
3. **樣本達標**：首次自訓練 → 個人化的頭（預期 ≥90%，向 97% 靠攏）

## 6. 置信度與失敗模式（誠實層）

- **escalate 閾值 v1 = 0.7**（softmax top1）。margin（top1−top2）<0.2 也 escalate。
- **失敗方向鐵則：寧多查不漏查**。實測唯一錯誤是誤查（安全側）；閾值調整只允許往「多查」方向偏。
- K1 的判斷永遠記錄在案（ledger）——錯了可回放、可歸因、可成為 K5 夢境議程（「這週 K1 漏查了幾次？」）。
- **K1 不做最終裁決**——它是路由器不是法官；LLM 永遠可以否決它（override 也記錄＝訓練樣本）。

## 7. 與生命樓／K 階梯的接點

- K1 的每次決策＋結果 → causal_ledger → **歷史主幹**（決策執行記錄）
- K1 判錯被 LLM 糾正的案例 → **歷史主幹子枝：想過但走岔的分支**（thought_branch 素材）
- 週期性 K1 錯題統計 → **K5 夢境議程**（精靈線索：漏查率、誤查率、escalate 率）
- 使用者的頭的訓練史 → 使用者自己的決策樹成長紀錄（開源食譜：每人地裡長自己的樹）

## 8. 驗收標準（以終為始）

| 項目 | 標準 | 驗法 |
|---|---|---|
| 延遲 | K1 全程 <150ms（含 embed） | 實測計時（今天 zero-shot 實測 108ms 已達標） |
| 二元準確率（自訓練後） | ≥90% | 對保留集（最近 20% 樣本）評估 |
| 漏查率 | <5%（安全側寧誤查） | 週統計入 K5 議程 |
| $9 同款題復測 | 生日題 K1 判 `need`＋檢索命中（1a59387a 修通後 top1=0.645） | 端到端哨兵測試 |
| 個人化可見 | 使用者能看到「K1 已用你的 N 條經驗訓練」 | 羅盤／能力中心顯示 |

## 9. 排程與切割

- **Phase 1**：`decision/` 三檔＋規則層＋ledger 樣本記錄（本週可動工）
- **Phase 2**：接進 agent loop 前置（sendMessage 進迴圈前過 K1）＋escalate 路徑
- **Phase 3**：自訓練迴路＋單調升級＋能力中心 UI
- **不在本稿範圍**：K2-K5、DecisionHead 換更強底座（等 DGX Spark）、多 companion 各自的頭（先共用一顆，樣本夠再分）
