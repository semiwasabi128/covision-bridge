## 發想 1：共視時長指標（Covision Duration）

### 問題
目前沒有任何指標區隔橋樑與其他 workflow 工具。n8n 和 Flowise 也有「使用時長」，但那是人「設定流程」的時間，不是人機共處的時間。

### 設計

**共視時長 = 使用者注意力與 Agent 注意力重疊在同一個畫布節點上的時間。**

偵測機制：
- 使用者注意力：Canvas visible + cursor/focus 在特定節點區域內
- Agent 注意力：Agent loop 正在處理與該節點相關的任務（工具調用、思考、生成）
- 重疊判定：兩者同時成立 → 累加共視時長

UI 呈現：
- 不做常駐計時器（會製造焦慮，違反 Bridge 設計原則）
- 在每日回顧或 Bridge Brain 面板顯示：今日共視時長、本週趨勢
- 可選成就：「共視 1 小時」「連續 7 日共視」等（遵循宣言 § 2.4 遊戲化原則）

### 技術可行性
- Canvas 狀態已有同步機制（brain_container）
- Agent loop 的「正在處理哪個節點」可從 `native_agent_loop.dart` 的事件流取得
- 需新增：attention overlap tracker（輕量服務，記錄時間戳）

### 驗收
- 畫面無常駐計時器
- 回顧面板顯示的數字與實際人機互動體感一致
- 數字不會因為背景執行而虛增

## 發想 2：發想素材池節點化（Idea Pool as Canvas Node）

### 問題
目前「橋樑發想素材池」是 Markdown 文件，等教練 Agent（或任何人）手動撈取。素材池的「撈 → 選 → 變成 Task」的循環，跟畫布上 input → llm → output 的循環結構完全同構，但它是不可見的。

### 設計

新增 Canvas 節點類型：`subWorkflow` 的變體——**素材池節點（Idea Pool Node）**。

節點行為：
- **輸入端口**：接收「種子主題」（如「本週橋樑發想」）
- **內部循環**：Agent 自動掃描素材池 → 按相關性排序 → 產出 3 條候選發想
- **輸出端口**：發想卡片（可被拖到畫布上成為獨立節點 → 進入工作流）
- **互動**：使用者可以在節點上標記「採用」「跳過」「改寫」→ 回饋給素材池排序

這讓「發想」本身變成畫布上可見、可連、可被 Agent 接管的循環——實現共視宣言 Layer 3「共同建造」。

### 技術可行性
- Canvas workflow engine 已支援 `subWorkflow` 節點類型（見 `references/canvas-workflow-engine-design.md`）
- 需新增：IdeaPoolNode widget + 素材池 JSON 讀取服務
- 互動標記需存回素材池（或衍生檔案）

### 驗收
- 素材池節點出現在節點選擇器
- 連接種子主題後，Agent 產出 3 條候選發想
- 使用者可將發想拖出成為獨立節點
- 標記「採用」的發想在素材池中被標記

## 發想 3：「走你的橋」社交動作（Walk Your Bridge）

### 問題
所有 workflow 工具（Langflow、Flowise、Rivet）把節點連成「流程圖」。橋樑把節點連成「橋」——但這個「橋」目前只在單人畫布上存在。如果橋是給人走的，那讓其他人也來走，就是最自然的社群動作。

### 設計

**「走你的橋」= 把一個畫布工作流分享給另一個人，讓他以共視模式打開。**

社交動作層級：
1. **分享橋**：把畫布工作流導出為 `.bridgepack` 格式（包含節點、連線、但不含私人資料/API key）
2. **走橋**：接收者打開 `.bridgepack`，以唯讀共視模式瀏覽——看到人機共同建造的過程
3. **延展橋**：接收者可以 fork 這份工作流，加上自己的節點 → 變成新版本 → 再分享

這對應宣言 § 5.2 Community Creation Layer 的 Workflow Quest Pack Spec。

### 技術可行性
- 畫布狀態已有完整的 JSON 序列化（CanvasSnapshot）
- 需新增：`.bridgepack` 格式定義（ sanitized export，移除敏感資料）
- 需新增：唯讀共視模式（限制編輯但保留同步）
- Fork 機制 → 社群二創 Registry（Phase 2）

### 驗收
- 畫布可匯出 `.bridgepack`
- `.bridgepack` 不含 API key、私人記憶、個人資料
- 唯讀共視模式可瀏覽節點連線與 Agent 軌跡
- Fork 後的新版本可在新使用者的畫布上編輯

## Phase F 排程建議

| 發想 | 建議時機 | 依賴 |
|---|---|---|
| 共視時長指標 | Phase F-1 | attention tracker + 回顧面板 UI |
| 發想素材池節點化 | Phase F-2 | Canvas subWorkflow 節點穩定 |
| 走你的橋 | Phase F-3 | `.bridgepack` 格式 + 唯讀模式 + 社群 Registry（Phase 2） |

三個發想可以獨立開發，但有自然順序：先讓共視可量化（F-1），再讓共視延伸到發想過程（F-2），最後讓共視延伸到社群（F-3）。

## 與共視宣言的對應

| 發想 | 共視宣言層次 |
|---|---|
| 共視時長指標 | Layer 1 共同看見 + Layer 2 共同感覺 → 量化 |
| 發想素材池節點化 | Layer 3 共同建造 → 在畫布上看見發想循環 |

> 共視不是旁觀。共視是兩個意識在同一個畫布上共同建造——這三個發想讓建造過程被看見、被量化、被分享。
