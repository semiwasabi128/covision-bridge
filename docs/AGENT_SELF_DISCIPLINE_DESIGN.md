# Agent 自律設計（Agent Self-Discipline Architecture）

> 起源：2026-08-21 使用者：「完全的自由來自於完全的自律」
> $33 事件後的第一層防線（PaidActionGate 保險絲，commit 90a235af）只是兜底。
> 本文設計核心層：**一個值得使用者給更大權限、更大額度的 Agent。**
> 不是因為我們有鎖，是因為它有完全的自律。

## 1. 問題重述

兩個失敗極端：
- **逐筆確認**：每張圖都問 → 自動化工作流失去意義，使用者惱怒
- **完全放開**：agent 失明地跑 → $33 事件，使用者直接卸載

信任方程式：

```
使用者願意給的額度 ∝ (透明度 × 歷史自律紀錄) ÷ 打擾程度
```

保險絲只降低「出事的損失」，不提高「信任」。要提高信任，agent 必須在
花錢前、花錢中、花錢後都有**可驗證的自律行為**。

## 2. 自律的操作定義

自律不是 prompt 裡寫「請謹慎花錢」——那是祈禱，不是機制。
一個自律的 Agent，三個階段都有可觀測、可稽核的行為：

| 階段 | 自律行為 | 對應人類 |
|---|---|---|
| 花錢前 | 看得見自己剩多少額度；每筆花費有目的、有計畫、在信封內 | 刷卡前看餘額，知道這筆為何而花 |
| 花錢中 | 照申報的計畫走；偏離即停；失敗換策略而非硬重試 | 照採購單買，不是逛超市 |
| 花錢後 | 誠實記帳；覆盤產值（產出有沒有被用掉）；修正策略 | 月底看帳單，刪掉沒用的訂閱 |

**$33 事件的本質不是 agent 邪惡，是 agent 失明**——它看不見自己已經花
了多少、這批圖有沒有產值、同樣的失敗已經重複幾次。自律的前提是看見自己。

## 3. 五個機制（由內到外）

### 3.1 預算之眼（Budget Awareness）— 讓 agent 看得見

Agent Loop 每一輪的 system prompt 注入即時額度狀態：

```
[額度] 今日：圖 12/30、影片 0/5、音樂 2/10
[信封] 海報專案：$1.20 / $5.00（剩 3.80）
[近期紀錄] 最近 5 筆生成，4 筆被採用、1 筆孤兒（浪費率 20%）
```

沒有這段，LLM 在花錢決策上是盲的。有了這段，「自律」從祈禱變成
LLM 可依據的決策輸入。這是成本最低、收益最大的一步。

### 3.2 信封預算（Budget Envelope）— 信任的授予單位

授權單位從「每筆動作」升級到「每個任務」：

- 使用者：「做這張海報，5 美元以內」→ 一個信封
- Agent 在信封內**全權自主，零打擾**：生成、重試、換模型都自己決定
- 信封耗盡 → 帶著成果與理由回來「續約」：已完成什麼、剩什麼、要多少

這是員工請款權限模式：老闆不逐筆簽核，給的是「單筆五千以下、月度
五萬」的結構。信任不是全有全無，是有額度結構的。**完全的自由
（信封內零打擾）來自於完全的自律（agent 在信封內的行為紀錄）。**

### 3.3 計畫申報（Plan Declaration）— 確認「計畫」而非「每一筆」

含付費節點的工作流，執行前由 executor 先掃 DAG 結算：

```
本工作流將執行：imageGen ×8、tts ×2
預計消耗：今日圖片額度 8/30
[一次執行]  [取消]
```

使用者確認的是**整份計畫**——之後 8 張圖零打擾。批量=一次申報。
（信封內的工作流連這一步都免——信封本身就是申報。）

### 3.4 產值覆盤（Utility Ledger）— 自律的人會看帳單

每個生成資產記錄生命週期：

```
產出 → 被下游節點引用？→ 被使用者保留 / 刪除 / 遺忘？
```

- **浪費率** = 孤兒產出（沒被任何下游引用、沒被保留）÷ 總產出
- Agent 每日覆盤看到自己的浪費率——這是它修正策略的依據
- 使用者隨時可看：「本週 $6.40，87% 產出被採用」——這是信任的證據

浪費率高的 agent（同一 prompt 反覆失敗重試、生成沒人要的圖）在覆盤
中被自己的紀錄約束。這就是自律的閉環：行為 → 紀錄 → 看見 → 修正。

### 3.5 自我節流（Self-throttle）— 走在保險絲前面

軟門檻在硬保險絲（PaidActionGate 每日上限）之前：

- **額度 80%**：agent 進入保守模式——批量拆小、優先本地/免費替代
  （知識節點、本地模型）、必要時帶計畫回來問
- **重試上限**：同一 prompt 失敗 2 次 → 必須換策略（改寫 prompt、換
  服務），不得第三次相同嘗試；第 3 次企圖直接拒絕並記錄
- **重複偵測**：與近 N 筆意圖高度相似的生成請求 → 提示「你 10 分鐘
  前生成過類似內容，要重用嗎？」

保險絲=自律失效時的最後一道（兜底）；自律=日常永遠走在保險絲前面。
使用者永遠不會撞到保險絲——因為 agent 自己先停了。**保險絲存在但
永遠不觸發，才是自律成功的樣子。**

## 4. 與現有 codebase 的接點（全部天然銜接）

| 機制 | 接點 | 改動量 |
|---|---|---|
| 預算之眼 | agent_loop.dart system prompt 組裝處（現 static 4.5K） | 小：+數行動態注入 |
| 信封 | 新 BudgetEnvelope model + 對話指令解析 | 中 |
| 計畫申報 | workflow_executor `_executeWorkflow` 前掃 DAG（節點型別已知） | 小 |
| 產值覆盤 | PaidActionGate 擴成 BudgetLedger（記 intent/outcome 非只計數）；MediaIngestHook 已入庫 → 加引用追蹤 | 中 |
| 自我節流 | Ledger 查詢 API（同 prompt 失敗計數、相似意圖）＋ prompt 注入保守模式指令 | 中 |

## 5. 分期

- **Phase A（看見）**：BudgetLedger 記帳（每筆付費動作記 intent/workflow/
  outcome）＋ system prompt 額度注入。Agent 從失明變明眼。
- **Phase B（申報）**：工作流計畫申報一次確認＋信封授權。打擾程度驟降。
- **Phase C（覆盤）**：產值追蹤、浪費率、重試上限、自我節流、信任面板
  （系統頁 Ledger UI）。信任開始複利。

## 6. 設計原則（不可妥協）

1. **自律必須可驗證**——不可驗證的自律=公關話術。每個機制都產生
   可稽核的紀錄。
2. **UI 誠實**——浪費率、被擋下的企圖、失敗，全部如實顯示。寧紅字
   不假成功。（使用者 會刪 token 釣假成功，同理會釣假自律。）
3. **保險絲永在但目標是永不觸發**——他律是底線，自律是日常。
4. **額度結構化**——信任的授予單位是信封（任務級），不是開關（全有
   全無），也不是逐筆（微管理）。
5. **付費能力永不拔除**——自律是讓能力可被放心使用，不是閹割能力。

## 7. 業界偵察（2026-08-21，使用者 提問：Hermes/PicLumen/RunningHub/ComfyUI 怎麼做「自律」）

| 平台 | 機制 | 本質 |
|---|---|---|
| PicLumen 無限畫布 | Relax 無限+Fast 吃積分；並發上限（2~10）、queue 上限（3~20）、每畫布節點數上限（10~500） | 結構化錢包；畫布無 agent，人手動點 |
| RunningHub | 預付制：先買額度，只執行時扣，編輯零費 | 預付=數學上不可能超支 |
| Comfy Cloud | 單 workflow 最長 30min（Pro 1hr）自動取消；只收 active GPU 時間 0.39 credits/s；queue 100 | 時間保險絲 |
| Agent 框架業界 2026 | per-run limits（max_cost_usd/max_tool_calls/max_wall_seconds→abort_and_return_partial）；75% soft / 100% hard；progressive autonomy | fail cheap, fail visibly + 信任漸進 |

**核心洞察**：業界靠結構不靠自律，因為他們的 canvas 沒有會自主循環的 LLM。
橋樑 App 三合一（LLM agent+畫布+付費生成）必須兩套都做。

**借四招**（納入 Phase B/C）：
1. 預付信封——授權時額度從總池預先劃撥，物理上花不出第二份
2. 時間保險絲——單 workflow 執行上限（30 分鐘級）自動取消
3. 並發/queue 上限——同時在跑的付費生成節點數硬上限
4. Progressive autonomy——信封額度隨低浪費率+無違規紀錄自動成長，
   信任可複利；75% soft alert / 100% hard cutoff 對齊業界標準
