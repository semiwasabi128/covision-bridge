# 夥伴狀態圖 (Companion State Graph) 設計文件

> **版本**: v0.1 草稿  
> **日期**: 2026-08-09  
> **作者**: 教練 Agent × 使用者  
> **狀態**: 待實作

---

## 一、問題：狀態散落各處

目前 Agent 的「狀態」分散在至少 4 個地方，彼此不連貫：

| 來源 | 變數 | 用途 |
|---|---|---|
| `ChatController._isLoading` | bool | 載入指示器 |
| `AgentActivityStage` | enum | 思考進度條（understanding/context/composing/routing/bridge） |
| `TransurfingEngine.StreamPhase` | enum | 水流生命週期 |
| `CompanionStatusSpec` | 9 種 | 桌面夥伴的表情/動作 |

**結果**：徽章顯示一個狀態、進度條顯示另一個、夥伴圖又是第三個——使用者看到的是碎片，不是一個「活著的角色」。

---

## 二、解法：統一狀態圖

用一套 **8 種狀態** 統一所有視覺回饋。每一種狀態對應：

1. **一張狀態圖**（夥伴姿勢——已有，在 `_defaultSheetPoses` 裡定義並生成）
2. **一個徽章樣式**（顏色 + 圖標 + 文字）
3. **一個動畫效果**（光帶、脈動、閃爍等）
4. **一個觸發條件**（Agent 的實際行為，不是關鍵詞）

---

## 三、8 種狀態完整定義

### 狀態 1：💧 漫遊 (Wandering)

```
┌─────────────────────────────────────────┐
│  ╭───────────╮                          │
│  │  🗺️ 探索   │  ← 徽章（灰綠底 + 探索圖標）│
│  │  原生 Agent      │                         │
│  ╰───────────╯                         │
│                                         │
│  ┌─────────────────────────┐           │
│  │                         │           │
│  │    [夥伴狀態圖：漫遊]     │  ← 夥伴在桌面閒晃
│  │    好奇地四處張望         │    帶俏皮小動作
│  │    輕鬆的步伐             │           │
│  │                         │           │
│  └─────────────────────────┘           │
└─────────────────────────────────────────┘
```

- **觸發**：使用者剛發訊息 / Agent 空閒等待
- **徽章**：灰綠底色，🧭 圖標，文字「漫遊中」
- **夥伴狀態圖**：漫遊姿勢——好奇、輕鬆、正在探索
- **動畫**：夥伴輕微左右搖擺
- **Transurfing 對應**：水流誕生 / idle

- **觸發**：Agent 回覆完成（自然結束——不需要使用者說「謝謝」）
- **徽章**：綠底色，✅ 圖標，文字「完成！」
- **夥伴狀態圖**：慶祝姿勢——小幅跳起、揮手或發光，開心、得意

## 四、Agent 行為 → 狀態自動觸發

**核心原則：不用關鍵詞，用 Agent 的實際行為。**

| Agent 行為事件 | 觸發狀態 | 來源 |
|---|---|---|
| 使用者發訊息 | wandering 漫遊 | `sendMessage()` 被呼叫 |
| LLM 開始推理 | reading 閱讱 | Agent Loop 第一輪 LLM 呼叫前 |
| `generate_image` / `web_search` / API | bridging 橋接 | 工具呼叫 dispatch |
| `write_file` / `patch` / 建資料夾 | writing 編寫中 | 工具回傳成功 |
| `memory_search` / `writeMemory` | idea 記憶中 | 記憶系統被呼叫 |
| Agent 回覆（自然結束） | celebrating 慶祝 | Agent Loop 結束 |
| 使用者切換話題 | stuck 暫停 | `detectTopicShift()` |
| 水流恢復 | pointing 指路 | `resumeStream()` |

### 水流完成判定（方案 B）

```
Agent 回覆完成
    ↓
狀態 → celebrating（光帶匯聚動畫）
    ↓
水流進入 awaitingConfirmation（不直接匯入）
    ↓
使用者下一句話：
    ├─ 繼續聊同一主題 → reactivateStream（水流延續，回到 reading）
    ├─ 切換話題 → pauseActiveStream（水流暫停，開新水流 → wandering）
    └─ 沒有下一句（沉默） → 30 秒後自動匯入
```

**不再需要「謝謝」觸發。** 光帶動畫在 Agent 回覆時就播放。水流是否匯入由使用者**下一個行為**決定。

## 五、8 種狀態圖生成提示詞（更新版）

以下為召喚夥伴時，每張狀態圖的生成提示詞模板。`{character}` 代表夥伴的外觀描述。

### 1. 漫遊 (Wandering)

```
{character} 正在桌面自由走動，好奇地四處張望，帶一點俏皮的小動作。
表情輕鬆好奇，步伐自在。背景透明，角色全身入鏡。
風格與主形象一致，角色設定圖姿勢。
```

- 觸發場景：平時陪伴、輕鬆探索、等待使用者或剛開始理解意圖時
- 行為描述：平時在桌面自由走動，帶一點俏皮的小動作
- 表情：好奇、輕鬆、正在探索

### 2. 閱讀 (Reading)

```
{character} 正在翻閱發光的頁面或筆記，整理上下文與記憶。
表情專注沉穩，正在思考。姿態微微前傾，像在認真研究。
背景透明，角色全身入鏡。風格與主形象一致。
```

- 觸發場景：正在讀取、整理、摘要、壓縮上下文或檢查資料時
- 行為描述：整理上下文與記憶，像在翻閱筆記或光頁
- 表情：專注、沉穩、思考中

### 3. 編寫中 (Writing)

```
{character} 正在用電腦或筆記本把想法整理成文字、程式或草稿。
表情努力專注，雙手忙碌地打字或書寫。姿態前傾認真工作。
背景透明，角色全身入鏡。風格與主形象一致。
```

- 觸發場景：當 Agent 正在寫程式、寫文案、寫草稿或執行內容產出時
- 行為描述：用電腦或筆記本把想法整理成文字、程式或草稿
- 表情：努力的編寫樣子

### 4. 橋接 (Bridging)

```
{character} 正在連接外部能力，身邊有穩定發光或能量流環繞。
表情認真可靠，正在施展能力的姿態。雙手伸向外部，像在牽引能量。
背景透明，角色全身入鏡。風格與主形象一致。
```

- 觸發場景：正在呼叫 API、連接外部服務、生成圖片或執行橋接任務時
- 行為描述：正在連接外部能力，身邊有穩定發光或能量流
- 表情：認真、可靠、正在施展能力

### 5. 卡住了 (Stuck)

```
{character} 苦惱中，雙手交在胸前，正在重新思考問題。
表情煩惱但不放棄，微微皺眉。姿態靜止，像在沈思。
背景透明，角色全身入鏡。風格與主形象一致。
```

- 觸發場景：遇到卡點、等待外部條件、需要使用者補充，或重複錯誤循環時
- 行為描述：苦惱中雙手交在胸前，正在重新思考問題
- 表情：苦惱中的樣子

### 6. 有好點子了 (Idea)

```
{character} 一隻手指向上方，上方有一個發亮的燈泡或光球。
表情微笑驚喜調皮，像突然想到了好辦法。姿態有精神，充滿活力。
背景透明，角色全身入鏡。風格與主形象一致。
```

- 觸發場景：回憶記憶成功、有好主意、好點子、好方法出現，或找到正確方向時
- 行為描述：一隻手指向上方，上方有一個發亮的燈泡
- 表情：微笑、驚喜、調皮

### 7. 指路 (Pointing)

```
{character} 伸手指向遠方的一座橋或下一個任務方向。
表情清楚有方向感，帶著鼓勵的微笑。姿態自信，像在引導旅伴。
背景透明，角色全身入鏡。風格與主形象一致。
```

- 觸發場景：水流恢復、從門回到母水流、正在判斷下一步、選工具、帶路或給使用者建議時
- 行為描述：伸手指向下一座橋或下一個任務方向
- 表情：清楚、有方向感、帶著鼓勵

### 8. 慶祝 (Celebrating)

```
{character} 任務完成後小幅跳起、揮手或全身發光慶祝。
表情開心得意，像完成一件好事。姿態有活力，充滿成就感。
背景透明，角色全身入鏡。風格與主形象一致。
```

- 觸發場景：任務完成、水流匯入、成果已生成或需要正向回饋時
- 行為描述：任務完成後小幅跳起、揮手或發光
- 表情：開心、得意、像完成一件好事

### 狀態轉換時的視覺序列（完整對話流程）

```
時刻 1: 使用者打字送出
┌───────────────────┐
```

## 九、備註

### 狀態圖組現有圖片怎麼用

每個夥伴在召喚時已生成了 8 張狀態圖（`generatedSheetImagePaths`）。key 對應：
`reading, writing, stuck, idea, pointing, bridging, celebrating, wandering`

新狀態枚舉直接用這些 key，不需要重新生成圖片。

### 為什麼不直接用 AgentActivityStage

`AgentActivityStage`（understanding/context/composing/routing/bridge）是 LLM 推理流程的階段，太抽象——使用者看不懂「understanding」。8 種夥伴狀態是直覺的——「閱讀」「橋接」「慶祝」，使用者一看就懂 Agent 在幹嘛。

### 光帶動畫為什麼不需要「謝謝」

因為 Agent 回覆本身就是一個完成節點。光帶動畫是在**Agent 做完事**時播放，不是在使用者說謝謝時。使用者的下一句話決定的是**水流是否延續**，不是**動畫是否播放**。
