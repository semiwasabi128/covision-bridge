# 刀 2 附錄：AgentGlyph 程序化指紋縮圖 — 設計補充

> 日期：2026-09-08 · Blue 概念令：「縮圖必須獨一無二——小葵跟小喬都是圓圈寫『小』就重複了」

## 一、為什麼不用 AI 生圖

AI 生圖每次不同（不確定性）、要花錢、離線不能用、且無法保證「不同 Agent 必不同」（可能撞風格）。縮圖的身份功能需要的是**確定性指紋**，不是美感。

## 二、AgentGlyph = 數學指紋

種子 = `sha-ish hash(companionId + name)`，展開成五層視覺：

| 層 | 來源 | 空間 |
|---|---|---|
| ① 底色 | hash → HSL 色輪（避開過暗/過亮/過髒） | ~200 色 |
| ② 外框形狀 | hash → 圓/方/六邊/花瓣 | 4 種 |
| ③ 圖案本體 | hash → 8×8 左右鏡像 identicon（32 bits） | 2³² 種 |
| ④ 光點裝飾 | hash → 0-3 顆 accent 光點位置 | ~200 種 |
| ⑤ 名字首字 | 中文名首字（輔助辨識，非主體） | — |

**獨特性保證**：組合空間 ≈ 200×4×2³²×200 ≈ 10¹⁴。實務上（App 內數十～數百個 Agent）碰撞機率趨近零；且主體是圖案③不是文字——「小葵」「小喬」同姓開頭也完全不同圖。

**確定性**：純函式繪製（CustomPainter），同 ID 跨裝置跨時間同一張臉——這是身份的前提。

**一石二鳥**：身份卡大圖（256px）與對話列表縮圖（18px）同源同 seed，只是解析度不同——「同一個 Agent 在任何地方都是同一張臉」。

## 三、消費端

1. **身份卡**：`_buildIdentityCard` 頭像區（有 avatarImagePath 用照片，沒有時用 AgentGlyph——新生成夥伴即刻有臉）
2. **對話列表**（Blue 第二個需求）：每行對話 trailing 顯示參與者 glyph 列（`messages.where(speakerId != null).map(speakerId).toSet()` 掃描，最多顯示 4 個＋「+N」）

## 四、驗證

- 確定性測試：同 seed 兩次生成 → 位圖相等
- 差異性測試：批次生成 100 個不同 ID → 圖案 bytes 全相異
- 無網路依賴、無 AI 呼叫
