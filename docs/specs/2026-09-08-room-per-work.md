## 一、這一刀解決什麼（G5）

**人類看到的不是 N 個 agent 的 N 個視窗，是一個房間裡的協作實況。**

現在的問題：任務的對話流在對話 tab、工作畫布在畫布 tab、產出物在交付卡、審計軌跡在身份卡——**同一件工作被拆在四個地方**，看一件事要跳四次。

刀 1 已經把三面牆打好了：TaskSession 綁 conversationId（對話流）＋workCanvasId（工作畫布）＋deliverables（產出物）。缺的只是**把它們放進同一個房間（同屏共居）**。

## 二、設計：任務卡展開＝房間

TaskProgressCard 展開區升級為「房間」——一張卡就是一件工作的實況：

```
┌────────────────────────────────────────────┐
│ ● 鹿角蕨照護計畫        working   ▾        │ ← 收合列（現有）
├────────────────────────────────────────────┤
│ 直播步驟流（現有——§5.1 三層直播）          │
├────────────────────────────────────────────┤
│ 🏠 房間視圖                                │
│ ┌────────────────┬────────────────────┐ │
│ │ 📝 對話流       │ ▦ 畫布縮圖          │ │
│ │ （最近 3 則     │ （工作畫布即時      │ │
│ │  該任務訊息）   │  縮圖＋開啟鈕）      │ │
│ ├────────────────┼────────────────────┤ │
│ │ 📦 產出物       │ 🛡️ 審計            │ │
│ │ （deliverables │ （該任務 Ledger     │ │
│ │  縮圖列）       │  統計+信任條）      │ │
│ └────────────────┴────────────────────┘ │
└────────────────────────────────────────────┘
```

### 2.1 四象限（2×2 grid）

| 象限 | 內容 | 資料源（全部現成） |
|---|---|---|
| 📝 對話流 | 該任務 conversationId 的最近 3 則訊息（role+內容摘要） | ConversationStore.getById |
| ▦ 畫布 | 工作畫布「開啟」卡片（名稱＋節點數＋開啟鈕→現有 onViewCanvas） | workCanvasId |
| 📦 產出物 | deliverables 縮圖列（圖片直接渲染） | session.deliverables |
| 🛡️ 審計 | 該任務的記帳統計（成功/失敗/浪費）＋小信任條 | BudgetLedger（D2.1 companionId 已接） |

### 2.2 多夥伴（報告的完整版——本刀做「單人房」）

報告說「多夥伴可被邀進同一房間」——這需要多 agent 派工（目前 dispatchTask 單夥伴）。**本刀先把房間做好（單人房），多夥伴邀請列刀 7 前置**（依賴意圖分類器多目標派工）。

**誠實聲明**：這是縮範圍，不是砍功能——房間容器先立起來，多夥伴是往房間裡加人，架構已預留（speakerId 已在訊息層）。

## 四、驗收

- 展開任一任務卡 → 四象限齊全（對話/畫布/產出/審計）
- 對話流象限顯示真實訊息（非假數）
- 點畫布象限「開啟」→ 跳畫布 tab 載入工作畫布（既有路徑）
- working 狀態時審計象限即時跳動（訂閱 dispatcher）
- lib/ 零 error；profile build 成功

## 五、一句話

**一件工作不再散落四個 tab——展開任務卡，整個房間就在眼前。**
