# M5b 作戰模式規格 v0.1 — 星系作戰層 × 回放 × 生命樹養分迴圈

> Blue 2026-09-23 令：作戰是重要數位資產。可重播複盤、可刪除；
> 戰績進生命樹（歷史樹+反思樹）非流水帳；羅盤出陣儀式（領工具包藥包）；
> 嚴禁形式化、不要臃腫。

## 一、系統全圖（一條龍）

```
┌─ 戰前 ─────────────────────────────────────────────┐
│ 羅盤出陣儀式：群任務 → 羅盤 → 領工具包+藥包 → 開戰閘門 │
│ （新：swarm_open 前置檢查——羅盤未領裝備=閘門 G0 擋下） │
└────────────────────────────────────────────────────┘
          ↓
┌─ 戰中（記錄）──────────────────────────────────────┐
│ SwarmRecorder：事件流記錄（append-only JSONL）        │
│   每事件 = {t, type, agentId, legion, data}          │
│   類型詞彙表（禁同義詞）：                             │
│   spawn/dispatch/progress/success/fail/intel/refute/ │
│   cost_tick/gate_pass/commit/end                    │
└────────────────────────────────────────────────────┘
          ↓
┌─ 戰後（三出口）─────────────────────────────────────┐
│ ① 星系作戰模式：模式切換列+「作戰」鈕 → 弱化長住層、    │
│   強化軍隊層、回放時間軸（時間之河同款 scrub/play）     │
│ ② 生命樹：指揮官統籌彙整 → 歷史樹（戰役記錄卡）+        │
│   反思樹（夢境議程素材：成功/失敗/遺憾三類養分）        │
│ ③ 資產：作戰紀錄檔可列出/重播/刪除（使用者主權）       │
└────────────────────────────────────────────────────┘
```

## 二、落地方案（三刀）

### 第一刀：SwarmRecorder（事件流記錄器）

`lib/services/collab/swarm_recorder.dart`

- 戰役 commit 時自動開錄；每個事件一行的 JSONL 檔
- 寫入點掛進既有系統（不新建平行系統——拒絕臃腫）：
  - `SwarmCommand.assertMaySpawn` 放行 → spawn 事件
  - `AgentStatusStore` setLive/setExited → progress 事件
  - delegate_batch 每兵完成 → success/fail 事件（帶 token 數）
  - IntelPool share/refute → intel/refute 事件
  - 蓋章點：每事件自動帶 cost（當下 ApiUsageTracker 讀數）→ 戰後對帳零成本
- 檔案：`~/Library/.../swarm_campaigns/<campaignId>.jsonl`
- **重播=讀 JSONL 逐事件重放**——與時間之河同哲學（忠實重播誕生過程）

### 第二刀：星系「作戰模式」（VIZ 第六模式）

`galaxy.html` + `swarm_layer.js` 擴充：

- 模式列（右上 bar）加「作戰」鈕（setVizMode('swarm')——與 river 同機制）
- 進入時：
  - **弱化長住層**：檔案星 opacity 0.15、記憶球 0.3、縫線 0.1（保留形狀感——「海」還在，但退成背景）
  - **強化作戰層**：軍隊全亮、四角框全開、指揮鏈線亮
  - **戰役選單**：列出歷史戰役（GET /galaxy_swarm_campaigns）→ 選擇載入
- **回放時間軸**（時間之河同款）：
  - 底部進度條+play 鈕（複用 river 的 tCursor/uOfW 引擎）
  - 重播=按事件 t 時間戳把兵星點亮/熄滅/移動/框呼吸
  - 成功兵=綠閃、失敗兵=紅閃、情報共享=金線脈動
- 退出作戰模式=恢復原樣（不污染長住層）

### 第三刀：生命樹養分迴圈（指揮官統籌入樹）

`lib/services/collab/swarm_harvest.dart`

- 戰役 done 時觸發（不即時——戰後統籌，符合「最後由指揮官統籌」）
- 流程（重用既有生命樹寫入口，零新平行系統）：
  1. 讀 SwarmRecorder JSONL → 統計：各軍團戰績、失敗模式、情報引用次數
  2. 生成三類養分卡（嚴禁流水帳——每場戰役最多 3 張）：
     - **成功經驗**：什麼打法有效（例：「研究軍 10 兵並行 wiki 檢索驗證率 92%」）
     - **失敗經驗**：什麼坑（例：「G4 試射跳過導致 3 兵 404 全滅」）
     - **遺憾經驗**：想打沒打的（例：「某分支兵未派出——下場可試」）
  3. 寫入：
     - 歷史樹：`agent_causal_ledger` 一張戰役卡（總兵數/耗時/成本/結局）
     - 反思樹：DreamService 議程注入（三類養分卡=下場夢的素材）
- 羅盤出陣儀式：swarm_open 加 G0 檢查——羅盤工具包+藥包未領 → 提示「先去羅盤領裝備」（讀 CompassStore 出陣登記表；詳 interactions 見規格尾部）

## 三、防臃腫三原則

1. **零新平行系統**：記錄掛既有事件點、生命樹走既有寫入口、回放複用 river 引擎
2. **JSONL 事後可棄**：入樹完成後 JSONL 只是重播資產（可刪——養分已萃取）；刪除=主權
3. **養分卡上限 3 張/戰役**：寧缺勿濫——指揮官 LLM 統籌時 prompt 明定「挑最有養分的三件事」
