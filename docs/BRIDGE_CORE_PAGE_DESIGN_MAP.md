# Bridge 核心頁面設計統合地圖

> **狀態**：v0.1 草案 · 2026-08-07
> **依據**：`lib/app.dart` 正式 GoRouter route 表；不以 prototype、死碼或 Coming Soon placeholder 作為設計核心。
> **上游裁決**：[Bridge 統合設計語言](BRIDGE_UNIFIED_DESIGN_LANGUAGE.md)

---

## 0. 用途

本文件不是 UI 截圖清單，也不是待辦羅列。

它回答每個核心工作域三件事：

1. 它首先服務使用者的哪一種任務？
2. 它應以 Layer A／B／C 的哪一層為主？
3. 未來改造時，什麼結果才算真的更像 Bridge？

---

## 1. 核心工作域總圖

```text
進入 Bridge
  ├── 入口與安裝：welcome / summon / pairing
  └── 開始工作
       ├── 工作桌面：bridge-desktop / desktop-homepage
       ├── 對話：chat
       ├── 共視與推演：brain-container / Canvas
       ├── 記憶與資料：master-folders / Vault
       ├── 關係與夥伴：companions / create / soul / appearance / voice
       └── 能力與可信設定：capabilities / settings
```

| 工作域 | 主要 route | 主層 | 次層 | 主要 Bridge 能力 |
|---|---|---|---|---|
| 入口與召喚 | `/desktop-welcome`、`/desktop-summon`、`/summon`、`/bridge-pairing` | A | C | 清醒、有回應 |
| 工作桌面 | `/bridge-desktop`、`/desktop-homepage` | A | B | 貼近、不斷線 |
| 對話 | `/chat` | A | B | 清醒、有回應、不斷線 |
| 大腦／共視畫布 | `/brain-container` | B | A、C | 可推演、不斷線、共視 |
| 記憶／資料夾／Vault | `/master-folders` | A | B | 貼近、可推演、可追溯 |
| 夥伴生命週期 | `/companions`、`/companion/create`、`/companion/soul`、`/companion/appearance`、`/companion/voice` | A | C | 貼近、有回應 |
| 能力與設定 | `/capabilities`、`/golden-keys`、`/settings` | A | — | 清醒、可信、可復原 |

## 2. 各工作域的設計契約

### 2.1 入口與召喚

**涵蓋**：桌面歡迎、桌面召喚、首次召喚、手機配對。

- **主任務**：讓首次使用者知道「現在要做什麼」並能安全地走進 Bridge。
- **主層**：Layer A。流程、文字與下一步優先。
- **Layer C 的資格**：只有「夥伴被確認／召喚完成」才可有短暫儀式感。
- **不可犯錯**：不能用神秘感取代指引；不能讓使用者不知道下一步或怎麼返回。
- **驗收句**：第一次進來的人，30 秒內知道自己正在建立誰、下一步按哪裡，以及能否修改。

### 2.2 工作桌面

**涵蓋**：`/bridge-desktop`、`/desktop-homepage`。

- **主任務**：成為所有工作域的穩定入口，而不是另一張功能海報。
- **主層**：Layer A；必要時用 Layer B 顯示工作關聯／目前進度。
- **必須保留**：位置感、目前工作上下文、可回到前一件事的路徑。
- **不可犯錯**：每個入口都長得像 CTA、所有資訊搶同一層級、切頁後失去上下文。
- **驗收句**：使用者從任何任務回來，都能一眼找到自己剛剛的工作與下一條可走路徑。

### 2.3 對話

**涵蓋**：`/chat`。

- **主任務**：人與 AI 的工作主線；文字要能被讀、回覆要知道正在發生什麼。
- **主層**：Layer A。Layer B 只在引用資料、計畫、卡片或接到 Canvas 時出現。
- **Layer C 的資格**：AI 開始思考、答案收束、重大任務完成；不得常駐。
- **不可犯錯**：用動態掩蓋模型狀態、把工具結果做成難以閱讀的裝飾卡、離開對話後丟失任務脈絡。
- **驗收句**：使用者在任何時刻都知道 AI 是否在工作、正在處理什麼、結果可以拿去做什麼。

### 2.4 大腦／共視畫布

**涵蓋**：`/brain-container` 與 Canvas。

- **主任務**：把關係、脈絡、計畫與共同注意力放進同一個可移動空間。
- **主層**：Layer B；Layer A 負責工具、選取、狀態與可讀文字。
- **Layer C 的資格**：節點關係被建立、共識形成、工作流成功等可指認事件。
- **不可犯錯**：只因為是 Canvas 就炫技；縮放、平移、選取後失去使用者位置；視覺效果攔截互動。
- **驗收句**：使用者和 AI 即使從不同入口進來，也能指向同一個節點、知道彼此正在看什麼。

### 2.5 記憶／資料夾／Vault

**涵蓋**：`/master-folders`、Vault 條目與關聯圖。

- **主任務**：讓資料可存、可找、可理解它與其他資料的關係。
- **主層**：Layer A；只有查詢關係、知識圖譜、來源追溯時進入 Layer B。
- **不可犯錯**：將檔案管理包裝成華麗畫布、看不清來源／篩選條件／排序、無法回到原始資料。
- **驗收句**：使用者可以回答「這筆資料從哪來、和誰有關、為何現在出現在我眼前」。

### 2.6 夥伴生命週期

**涵蓋**：夥伴館、建立、靈魂、外觀、語音。

- **主任務**：建立可理解、可調整、可持續互動的夥伴關係。
- **主層**：Layer A，親近感由資訊與語氣建立，不靠滿版特效。
- **Layer C 的資格**：完成召喚、人格確立、連結建立；必須是一個可命名的儀式事件。
- **不可犯錯**：把設定流程做成沒有返回與確認的儀式、以動畫取代清楚選項、讓角色外觀壓過關係內容。
- **驗收句**：使用者任何時刻都知道正在調整夥伴的哪個面向，以及此變更是否真的生效。

### 2.7 能力與可信設定

**涵蓋**：`/capabilities`、`/golden-keys`、`/settings`。

- **主任務**：使用者能理解能力、授權與本地／雲端狀態，並安全改變它。
- **主層**：純 Layer A。安靜、明確、可復原。
- **禁止**：氣氛粒子、無意義轉場、依賴顏色而不提供文字狀態。
- **驗收句**：使用者知道一個能力是否可用、資料去哪裡、失敗如何修、改動如何撤回。

## 3. 設計改造優先級

設計改造不以「哪頁最醜」排序，而以它是否承載 Bridge 的核心承諾排序。

| 優先 | 工作域 | 原因 | 先驗收什麼 |
|---:|---|---|---|
| P0 | 對話 | 人與 AI 的主工作線；所有其他能力最終都要回到這裡 | 模型／工具／任務狀態是否清醒且不中斷 |
| P1 | 大腦／Canvas | Bridge 的共視差異化所在（[共視宣言](COVISION_MANIFESTO.md)） | 位置感、共同指向、關係可推演 |
| P1 | 工作桌面 | 決定使用者會不會迷路 | 上下文回流與下一步可見性 |
| P2 | Vault | 支撐 AI 記憶、資料可信度與追溯 | 來源、關係、搜尋結果的可解釋性 |
| P2 | 夥伴生命週期 | 關係感要建立在可控而非炫技 | 每個設定是否可理解、可確認、可返回 |
| P3 | 入口與召喚 | 儀式感重要，但不能先於日常工作骨架 | 首次流程的清楚、可信與可返回 |
| P3 | 設定／能力 | 需持續乾淨，通常不需要先做視覺大改 | 狀態、風險、修復路徑 |

## 5. 下一輪輸出

本地圖完成後，下一輪不是立刻重畫所有頁面，而是對 P0 的 `/chat` 做一份 **[設計診斷卡](CHAT_P0_DESIGN_DIAGNOSIS.md)**：

1. 現在使用者能否看懂 AI／工具／本地模型的狀態？
2. 哪些元素正破壞清醒、回應或不中斷？
3. 能否只改 token、Tier、狀態層與 layout hierarchy，而不破壞功能鏈？
4. 需先完成 Call-Site Trace 的互動／服務有哪些？

這樣設計統合會進入產品，而不是停留在文件裡。
