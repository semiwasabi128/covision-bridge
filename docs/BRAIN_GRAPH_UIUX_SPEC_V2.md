## 二、資訊呈現四層制（標籤系統重定義）

> 使用者 原則：「標籤本身可以用顏色來呈現，節點上第一層顯示的字應該是它的標題字，
> 點選之後才在旁邊出現詳細資料。」

### 節點身上只承載「顏色＋大小」，文字是分層揭露的：

| 層 | 觸發 | 顯示什麼 | 資料來源 |
|---|---|---|---|
| L0 遠景 | scale < 0.4 | 只有顏色點＋集群標題（房間名） | room |
| **L1 常態** | 0.4 ≤ scale | **內容標題**（每節點獨一無二的那句話） | `display_title`（新欄位） |
| L2 hover | 滑鼠懸停 | 完整分類＋摘要＋來源＋時間 | metadata 全展 |
| L3 點擊 | 單擊 | 側欄 detail panel（既有） | 既有 |

### L1 的關鍵改變：sub_category 從「文字」降級為「顏色」

- 節點**不再**顯示「共振」「順暢流動」這種分類字——它們改由**顏色編碼**表達
- 每個節點顯示的是它自己的標題：
  - 記憶節點 → content 的前 N 字（剝掉「使用者正在…」句式）
  - 檔案節點 → `display_title`（ingest 時產生的人類可讀標題，見第四节）

### 顏色系系統化（取代 emoji 圖例）

圖例（畫布底部）從 emoji 改為**色點＋房間名＋計數**：

```
● 水流軌跡 71   ● 門的紀錄 16   ● 擺錘警報 5
● 心腦對話 176   ● 靈魂頻率 321   ● 橋樑 52
```

- 六房間各綁一個**固定色相**（色盲友善：除了色相再加亮度差異）
- 檔案節點：同一色相的**低飽和版**（人類資產暖色系、agent 產出冷色系——來源分層，見鐵三角文件）
- hover 圖例項目 = 該房間以外的全部淡出（圖例即篩選器）

## 三、線的三層制 v2（修正「線太少」）

> 使用者 原則：聚攏是第一層連線（已刪相似邊是對的），
> 但「拉近時可以看到樹狀或葉脈結構」——現在連葉脈都沒了。

### 問題診斷

砍掉相似邊後，剩下的引用邊只有「記憶↔檔案」幾百條，且集中在檔案星系——
記憶星系之間幾乎沒線，所以「點跟點之間沒有聚攏效果」。

### 修正：線的語義分層不變，但「葉脈層」用佈局語言重建

| 層 | 視覺 | 資料 | 何時顯示 |
|---|---|---|---|
| 主動脈 | 粗亮線＋脈動 | 跨房間嵌入相似（模式4的跨島橋）→ 常駐 | 全縮放 |
| 血管 | 中線 | 引用/裙帶（記憶↔檔案） | scale ≥ 0.4 |
| **葉脈** | **極細半透明** | **同房間 top-1 嵌入相似**（只連每點最強的 1 條，斷開成樹狀） | **scale ≥ 0.7 才顯示** |

- 葉脈層 = 每節點只連「最相近的那一個」同房間鄰居 → 自然形成樹/葉脈狀，
  不會回到毛球（top-1 而非 top-3，且只在近景顯示）
- 聚攏感由佈局提供（力導），葉脈由線提供——兩者合力，單獨都不夠

## 四、ingest 為圖譜服務（根因治理）

> 使用者 原則：「標籤、備註、標題、關聯，都要『為了圖譜展現而服務』也
> 『為了 agent 調用而服務』，這兩者應該不衝突。」

### schema 增補（細節見 RESEARCH_DETECTIVE_INGEST_FRAMEWORK.md）

`asset_index` 與 `memories` 新增三個 ingest 時產生的欄位：

| 欄位 | 服務誰 | 產生時機 |
|---|---|---|
| `display_title` | 圖譜（L1 標題）＋ agent（引用時報出可讀名） | ingest 掃描時：.md 取 H1/首行；照片取日期+主題；機器產出取任務名+日期 |
| `origin_kind` | 圖譜（顏色分層：人類/agent/農場）＋ agent（來源過濾） | ingest：路徑+產生者推斷 |
| `topic_cluster` | 圖譜（葉脈層預算）＋ agent（聚類檢索） | ingest 後批次：嵌入 k-means |

### 「偵探式導入」（空白 App 的安裝精靈）

1. 使用者選資料夾 → **掃描**（檔案類型統計、命名模式、時間聚類）
2. **判讀**：推斷使用者畫像（攝影師？開發者？自媒體？）→ 決定分類策略
3. **抽樣標註**：每類抽 20 筆給 LLM 標 display_title/topic → 人類確認一次
4. **全量套用**＋增量更新（新檔案進來走同一條管線）

## 五、點擊錯位修復原則（等驗屍報告確認根因）

無論根因是哪個（Q 彈動畫座標漂移／hitTest 表不同步／座標系混用），
修復後的驗收標準：

- [ ] 任意縮放下，點擊視覺上看到的點，選中的就是那個點
- [ ] 動畫進行中（Q 彈/擺動）點擊仍然準確（hitTest 用動畫當下的位置）
- [ ] hitTest 半徑以**螢幕像素**計（世界半徑 × scale），最小 12px 觸控面積
- [ ] 節點重疊時，點擊選**最上層/最近**的，不是列表裡第一個
