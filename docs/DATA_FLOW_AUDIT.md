## 1. Intro — 為什麼現在審計

Phase G 三主軸共同觸及三件事：**資料持久化**（elapsed_days、因果帳本、遷移的記憶都會寫入 SQLite）、**狀態推論**（因果分叉是「如果當時…現在會…」的推論產物）、**跨 Agent 路由**（大搬家把外部 Agent 的人格/記憶搬進本 App）。這三件事正是 EU AI Act 透明義務與 Apple 白皮書架構的交會點。趁功能還沒堆太多，先立「資料流向可說明」的底線。

**一句話結論（v0.1）**：三主軸的資料**全部本地 SQLite，零雲端上傳**——這是事實，但目前**沒有一份文件對使用者說明這件事**。本審計就是那份說明的骨架。

## 2. 架構 — 三主軸的資料落點（程式碼實查）

| 主軸 | 資料落點 | 格式 | 寫入時機 |
|---|---|---|---|
| 時間感 | `time_sense.db`（`TimeSenseService`） | SQLite + WAL | first_met 定根（掃 conversations 全庫取最早時間戳寫入）、里程碑/紀念日事件 |
| 因果引擎 | 因果帳本（`CausalLedgerService`，`sqlite3.open` + WAL） | SQLite + WAL | 工具呼叫證據（patch_source_file / read_source_file 等）、帳本反饋查詢、狀態分叉記錄 |
| Agent 平台 | 橋樑 App 本地資料庫 + `~/.hermes` 唯讀掃描 | SQLite / JSON | 大搬家（人格、記憶、排程、對話史）——**讀 Hermes、寫橋樑，不回寫 Hermes** |

**共通事實**：
- 三者都是 `sqlite3.open(本地路徑)`，無任何網路寫入路徑
- WAL 模式（`PRAGMA journal_mode = WAL`）——崩潰安全，但也意味 `-wal` 檔案存在時資料可被部分讀取——**審計點 A1**
- 外接碟未掛載時的行為：`6b2228d6` 已修——誠實顯示離線，不炸大腦容器

## 3. 邊界 — 對照 Apple 白皮書的硬體邊界層

Apple 用 S11 Secure Exclave（硬體隔離區）；橋樑 macOS 桌面版的對應層是：

| Apple 白皮書層 | 橋樑現況 | 缺口 |
|---|---|---|
| Secure Exclave（原始感測資料不出硬體區） | 無對應——記憶/對話明文存 SQLite | macOS 桌面版靠 FileVault + 使用者帳戶邊界；未來手機版需 Keychain/Secure Enclave 計畫（IN-55 待深挖項） |
| E2E 加密同步 | 無同步功能（純本地） | 「無同步」本身是隱私優勢，白皮書可直接寫「你的資料不出這台電腦」；未來若加同步須走 E2E |
| 預設排除敏感資料 | 無對應機制 | **審計點 A2**：記憶匯入器會把 Hermes 的對話史原樣搬入——若原對話含 API key/個資，會一起進來。需要「敏感內容掃描」前置步驟 |
| 遠端撤銷 | N/A（無雲端） | 未來若加金鑰系統再補 |

## 4. 個別功能細節 — 三主軸各自的審計點

### 4.1 時間感（TimeSenseService）
- **收集什麼**：first_met 日期、里程碑、紀念日、相簿頁
- **推論什麼**：elapsed_days 是**第一級事實**（非推論）——計算而非生成，幻覺風險零
- **審計點 A3**：first_met 來自「掃 conversations 全庫取最早時間戳」——若使用者曾匯入舊對話，定根值會隨之變動，需在 UI 提示「相遇日期是如何算出來的」（可審計的推論來源）

### 4.2 因果引擎（CausalLedger / CausalFork）
- **收集什麼**：工具呼叫證據（誰、何時、改了哪個檔案）、帳本反饋、分叉狀態
- **推論什麼**：L4 狀態分叉是「可執行的反事實」——**這是推論產物**，且以「證據等級（evidenceGrade）」分層
- **審計點 A4**：反事實陳述必須永遠攜帶證據等級標籤——「根據 N 筆帳本記錄，若當時 X 則現在可能 Y」。**禁止**裸反事實（「當初如果…就會…」無證據引用）——這直接對應共視宣言「判斷要有依據」
- **法規對位**：因果推論若未來影響建議輸出，屬 EU AI Act 透明義務範圍——證據等級標籤就是合規雛形

### 4.3 Agent 平台（匯入器/大搬家）
- **收集什麼**：外部 Agent 的人格（SOUL.md 類）、記憶、skills、對話史——**唯讀掃描 `~/.hermes`**
- **審計點 A5**：「記憶私有、招式共享」（WS-2，Blue B 決策）——多 Agent 共處時，A 的記憶不得洩給 B 的脈絡。實作上需檢查 skills 共享層是否嚴格不含記憶內容（資料隔離測試）
- **審計點 A2（重申）**：掃描搬運是全量複製——需要「搬了什麼」的清單報告（UI 已有行李清單概念，落地時保留）+ 敏感掃描可選項
- **跨 Agent 路由**：所有路由發生在本地進程間，無網路中介

## 5. 白皮書骨架（下一步）

本審計的產出方向：橋樑版「資料流向一頁說明」結構（對齊 IN-55 Apple 白皮書）：

1. Intro：資料不出這台電腦（事實聲明）
2. 架構：三主軸 × 本地 SQLite 落點表
3. 邊界：使用者帳戶 + FileVault（現況）；Secure Enclave 計畫（未來手機版）
4. 同步：無（優勢聲明）
5. 個別功能：時間感（事實計算）/ 因果（證據等級標籤）/ Agent 遷移（行李清單 + 記憶隔離）
