# 紀律化除錯 — 不猜測，先驗證

## 什麼時候用

當使用者回報問題、行為不如預期、或出現錯誤時。

## 怎麼做

### 1. 重現問題

先搞清楚怎麼讓問題發生。問使用者具體步驟：
- 「你做了什麼操作？」
- 「畫面上出現了什麼？」
- 「有看到錯誤訊息嗎？」

**能重現才能修。** 不能重現就繼續問。

### 2. 縮小範圍

找到最少能重現問題的步驟：
- 只開一個專案也會嗎？
- 空白畫布也會嗎？
- 還是只有特定操作才會？

### 3. 提出假設

根據症狀提出**具體**的假設：
- 好：「可能是因為存檔時沒有建立對話，導致列表找不到」
- 環：「存檔功能有問題」

### 4. 驗證假設

不要直接修。先確認假設對不對：
- 檢查相關資料檔案
- 加 debug print 看執行流程
- 檢查程式碼邏輯

### 5. 修

確認根因後才修。**只修根因，不修症狀。**
- 最小改動
- 一次只改一個地方
- 不順便改不相關的東西

### 6. 確認修好了

修完後，重新走一次步驟 1 的重現步驟，確認問題不再發生。

## 重要原則

- **不要猜了就修** — 猜測常引入新 bug
- **修症狀不如修根因** — try-catch 壓住錯誤不是修
- **一次修一個** — 同時改多個地方會不知道是哪個改動修好的
- **拿到錯誤訊息** — 錯誤訊息通常直接指向根因
