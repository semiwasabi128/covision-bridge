# 需求轉規格 — 討論完寫成文件

## 什麼時候用

跟使用者討論完需求後，整理成文件讓使用者確認。

## 怎麼做

### 1. 回顧討論

整理剛剛討論的內容，確認你理解了使用者的需求。

### 2. 寫規格

用這個格式：

```
## 功能：[名稱]

### 為什麼要做
[白話描述動機]

### 使用者故事
- 身為使用者，我想要 [做什麼]，這樣 [好處是什麼]
- 身為使用者，當我 [觸發條件]，我期望 [結果]

### 正常流程
1. 使用者 [做 X]
2. 系統 [做 Y]
3. 使用者看到 [Z]

### 邊界情況
- 如果 [特殊情況] → [應該怎麼辦]

### 完成標準
- [ ] [可檢查的條件1]
- [ ] [可檢查的條件2]
```

### 3. 給使用者確認

問「這份規格對嗎？有沒有需要改的？」使用者確認後才開始做。

## 重要原則

- **寫行為，不寫實作** — 「按存檔時把工作流存起來」是行為，「呼叫 CanvasStore.saveCanvasToProject」是實作
- **包含邊界情況** — 討論中發現的特殊情況一定要寫進去
- **完成標準要可檢查** — 「存檔功能正常」太模糊，「按存檔後 sidebar 出現新專案」才具體
- **不要太長** — 1-2 頁就好，太長表示功能太大要拆
