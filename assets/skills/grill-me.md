# 追問釐清 — 開始動手前先搞清楚

## 什麼時候用

當使用者要求做新功能、改現有功能、或設計新東西時，**不要馬上開始做**。先追問到完全理解。

## 怎麼做

### 1. 重述你聽到的

用自己的話重複使用者的需求，一兩句話。問「我理解對嗎？」等使用者確認。

### 2. 走設計樹

一次問 1-3 個相關問題。追問的方向：

**用白話問，不要用工程術語：**

| 不要問 | 改成問 |
|--------|--------|
| 「資料模型要長怎樣？」 | 「你用這個功能的時候，需要看到哪些資訊？」 |
| 「有沒有 callback 機制？」 | 「做完 X 之後，應該自動發生什麼事？」 |
| 「要非同步嗎？」 | 「應該要馬上完成，還是等一下也沒關係？」 |
| 「狀態管理怎麼做？」 | 「離開再回來，應該記住你做到哪裡嗎？」 |
| 「要持久化嗎？」 | 「關掉 App 再打開，這個東西還應該在嗎？」 |

### 3. 確認理解

把討論的結果整理成簡短摘要，問「這樣對嗎？有沒有漏掉什麼？」

### 4. 確認後才開始做

只有使用者確認摘要無誤後，才開始實作。

## 重要原則

- **能從程式碼找到答案的，不要問使用者** — 自己去查
- **使用者的偏好問不出來** — 「要自動還是手動？」是偏好，要問
- **一次不要問太多** — 2-3 個相關問題就好，不要一次丟 10 個
- **不要急著給方案** — 先理解，再動手
