# 自我檢查 — 交出去前先看一遍

## 什麼時候用

功能做完、要告訴使用者「好了」之前。或使用者要求檢查時。

## 檢查什麼

### 1. 一致性

- 新的程式碼有沒有跟旁邊的程式碼風格一致？
- 變數命名有沒有跟現有的一致？
- 顏色有用 `BridgeDSColors.of(context)` 嗎？（不是硬編碼顏色）
- 文字有沒有用繁體中文？

### 2. 完整性

- 使用者要的功能都做了嗎？
- 邊界情況有處理嗎？
- 離開再回來還能用嗎？
- 關掉 App 再打開資料還在嗎？

### 3. 資源管理

- 有新增 Controller、Notifier、Listener 嗎？有在 dispose() 裡釋放嗎？
- 有新增回呼（callback）嗎？呼叫前有檢查 null 嗎？
- 有非同步操作嗎？mounted 檢查了嗎？

### 4. 連鎖反應

- 改了這個，有用到同樣東西的地方需要一起改嗎？
- 新增的 UI 有在所有 tab 都正常嗎？
- 切換 tab 再回來還正常嗎？

## 發現問題怎麼辦

- **先修再交給使用者** — 不要把已知問題丟給使用者測試
- **修不了的記下來** — 告訴使用者「這個已知問題我之後會修」
- **修完重新檢查** — 修一個問題可能引入新問題

## 重要原則

- **每一行改動都看過** — 不要只看大概
- **不只是能跑就好** — 能跑但有 memory leak 也是問題
- **假設會出錯** — 想像使用者在最奇怪的操作順序下會發生什麼
